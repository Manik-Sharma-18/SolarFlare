  <action>
Rewrite `models/uncertainty.py`:

1. **predict_with_uncertainty — Welford's algorithm:**
   - Remove the `predictions = []` list and `torch.stack` pattern.
   - Instead, maintain three accumulators: `count` (int), `mean` (tensor), `m2` (tensor).
   - Initialize `mean` and `m2` as `torch.zeros_like(first_pred)` after the first forward pass.
   - For each MC forward pass:
     ```
     count += 1
     delta = pred - mean
     mean += delta / count
     delta2 = pred - mean
     m2 += delta * delta2
     ```
   - After all passes: `variance = m2 / count`, `std = torch.sqrt(variance + 1e-8)`.
   - Use `try/finally` to ensure model mode is restored even if forward pass raises.
   - The caller is responsible for passing one dataset sample at a time. The function runs all n_samples MC forward passes for that single input, accumulating via Welford's, before returning. This honors the locked decision: "process one sample at a time through all MC passes before moving to next — minimal peak memory."
   - Keep the same function signature and return type: `(mean, std)`.

2. **predict_with_confidence_intervals — Gaussian approximation (no quantiles):**
   - Remove `torch.quantile` usage entirely. Do NOT import or use `safe_quantile`.
   - Apply Welford's algorithm (same as predict_with_uncertainty) to get mean+std.
   - Compute confidence intervals as `mean +/- z * std` where z comes from the confidence level (e.g., 1.96 for 95%). This is a Gaussian approximation, valid for n_samples >= 20 by CLT.
   - This honors the locked decision: "compute mean + std only from MC passes (no quantiles needed)."
   - Update docstring to note this uses Gaussian approximation instead of empirical quantiles.

3. **uncertainty_weighted_loss — keep unchanged.** This function receives pre-computed uncertainty, no changes needed.

4. Add comment at top of module noting Welford's algorithm reference.

Modify `clear_device_cache()` in `utils/device.py`:

1. Add `import gc` at top of file.

2. For MPS and CUDA device types (not CPU):
   - Call `gc.collect()` BEFORE calling `torch.mps.empty_cache()` or `torch.cuda.empty_cache()`.
   - This releases Python-side references to tensors before asking the device runtime to reclaim memory.
   - Comment explaining: "gc.collect() releases dangling Python tensor references before device cache clear — critical for MPS which has known memory leak issues with unreferenced tensors."

3. CPU branch: remain a no-op (no gc.collect either — CPU memory is managed by the OS/Python GC naturally).

The function is already called after validation in trainer.py (wired in Phase 1), so no additional call sites needed.
