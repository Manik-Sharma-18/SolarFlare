Update config defaults to v3.0 architecture values, set up optimizer parameter groups for delta_scale exclusion from weight decay, and add attention entropy logging as an overfitting diagnostic.

  <name>Task 2: Add attention entropy logging to validation</name>
  <files>training/trainer.py</files>
  <action>
    Add attention entropy computation and logging as an overfitting diagnostic during validation.

    **1. Add entropy computation helper** at the top of trainer.py (after imports, before class definitions):

    ```python
    def _compute_attention_entropy(attn_weights: torch.Tensor, eps: float = 1e-8) -> float:
        """Compute Shannon entropy of attention distribution.

        Args:
            attn_weights: (B, T) or (B, C) attention probabilities (sum to 1 along last dim)

        Returns:
            Mean entropy across batch (scalar)
        """
        log_attn = torch.log(attn_weights + eps)
        entropy = -(attn_weights * log_attn).sum(dim=-1)  # (B,)
        return entropy.mean().item()
    ```

    **2. Modify validate() to collect attention entropy:**

    The challenge: TemporalAttention returns attn_weights as a second output in its forward(), but the predictor's forward() does not currently expose these. Two approaches:

    Approach A (simpler, recommended): Use a forward hook on the temporal_attn module to capture attention weights during validation. This avoids modifying predictor.forward() return signature.

    In validate(), before the validation loop:
    ```python
    # Collect attention entropy if temporal attention is available
    temporal_attn_entropies = []
    _attn_hook_handle = None

    if hasattr(model, 'temporal_attn') and hasattr(model, 'use_temporal_attention') and model.use_temporal_attention:
        def _capture_attn_weights(module, input, output):
            context, attn_weights = output
            temporal_attn_entropies.append(_compute_attention_entropy(attn_weights))

        _attn_hook_handle = model.temporal_attn.register_forward_hook(_capture_attn_weights)
    ```

    After the validation loop (before returning):
    ```python
    if _attn_hook_handle is not None:
        _attn_hook_handle.remove()

    # Compute mean temporal attention entropy across all validation batches/steps
    if temporal_attn_entropies:
        import math
        t_in = next(iter(dataloader))[0].shape[2] if False else 10  # avoid extra iteration
        # Actually, just use the collected values directly
        metrics['temporal_attn_entropy'] = sum(temporal_attn_entropies) / len(temporal_attn_entropies)
    ```

    Wait -- using a hook is cleaner but we need to be careful. The temporal_attn.forward() is called t_out times per sample (once per decoder step). The hook fires each call. So temporal_attn_entropies will have len = num_batches * t_out. That's fine -- we average all of them.

    Actually, a simpler approach: just compute the mean entropy value across all hook captures.

    ```python
    if temporal_attn_entropies:
        metrics['temporal_attn_entropy'] = sum(temporal_attn_entropies) / len(temporal_attn_entropies)
    ```

    Add to history initialization:


    After validate() call in the epoch loop, append:


    **4. Add entropy to epoch console output:**

    After the existing validation metrics print (around where CSI/HSS are printed), add:

    ```python
              f"(max: {max_entropy:.3f})")
    ```

    **5. Do NOT add channel attention entropy at this time.**
    The SAM module's channel attention operates internally within each cell. Capturing it would require hooks on each of the 6 SAM modules and averaging across layers, which adds significant complexity. The temporal attention entropy is the more important diagnostic (tells us if the model fixates on one input timestep). Channel attention entropy can be added in Phase 11 if needed. Document this choice in the summary.
