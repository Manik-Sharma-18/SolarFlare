## Data Storage

**Input Data:**
- Local filesystem only
  - Raw solar flux data: `.npy` structured arrays containing (X, Y, time, windTotal fields)
  - Location: `config['data']['data_dir']` (default: `./data/`)
  - Format: NumPy structured arrays with fields: X, Y, time, windTotal

**Preprocessed Data (Optional):**
- Local filesystem caching
  - Preprocessed cubes: `.npz` files (numpy compressed format)
  - Location: `config['data']['preprocessed_dir']` (default: `./data_processed/`)
  - Generated by: `preprocess_data.py`
  - Used for fast loading during training (avoids re-computing structured-to-cube conversion)

**Model Checkpoints:**
- Local filesystem storage
  - Location: `config['output']['save_dir']` (default: `./outputs/`)
  - Checkpoint file: `config['output']['checkpoint_name']` (default: `best_model.pt`)
  - Contains: Model state dict, epoch number, validation loss
  - Saved by: `training/trainer.py` during training (best epoch only)

**Metadata & Results:**
- JSON files saved to output directory
  - `metadata.json` - Data statistics, normalization parameters, split info
  - `test_results.json` - Test loss and MAE per timestep
  - `training_history.json` - Training/validation losses per epoch

**Visualization Output:**
- PNG images saved to output directory
  - `training_history.png` - Loss curves
  - `predictions.png` - Sample predictions vs ground truth
  - `uncertainty_sample_*.png` - MC Dropout uncertainty maps (if enabled)

**No Cloud/Remote Storage:**
- No database connections (PostgreSQL, MongoDB, etc.)
- No cloud storage integrations (S3, GCS, etc.)
- No remote model registries (MLflow, Weights & Biases, etc.)

## Input/Output Formats

**Input Data Format:**
- NumPy structured arrays (.npy files)
- Fields: X (spatial), Y (spatial), time (temporal), windTotal (flux value)
- Converted to dense cubes: (T, H, W) shape
  - T: Temporal timesteps
  - H: Height (spatial dimension)
  - W: Width (spatial dimension)

**Preprocessed Format:**
- `.npz` files (NumPy compressed archive)
- Contains single key `'data'` with normalized flux cube

**Model I/O:**
- Input tensor shape: `(B, C, T_in, H, W)`
  - B: Batch size
  - C: Input channels (1 for flux only, 2 for flux + extreme indicator)
  - T_in: Input timesteps
  - H: Height, W: Width
- Output tensor shape: `(B, C_out, T_out, H, W)`
  - C_out: Output channels (typically 1 for flux prediction)
  - T_out: Predicted timesteps

**Checkpoint Format:**
- PyTorch `.pt` file (pickled dictionary)
- Keys: model_state_dict, optimizer_state_dict (optional), epoch, val_loss, config

**Output Formats:**
- Predictions: NumPy arrays or torch tensors
- Visualizations: PNG images
- Results: JSON (test_loss, metrics)
- History: JSON (per-epoch losses)

## Normalization & Preprocessing

**Normalization Methods** (configured via `config['normalization']['method']`):

1. **Asinh (Recommended):**
   - Transformation: `arcsinh(x / softening) / scale`
   - Preserves sign and compresses dynamic range
   - Parameter: `asinh_softening` (default: 1000.0)
   - Detects extreme events: percentile-based threshold
   - Location: `solarflare_data/loader.py` (_compute_norm_params)

2. **Robust (Percentile-based):**
   - Center: Median of data
   - Scale: (p99 - p1) / 2
   - Parameters: `percentile_low`, `percentile_high` (default: 1, 99)
   - Robust to outliers

3. **Fixed:**
   - Simple division by constant factor
   - Parameter: `fixed_factor` (default: 40000.0)
   - Fast but less adaptive

**Data Augmentation:**
- Horizontal flip (50% probability)
- Vertical flip (50% probability)
- Consistent across input-output pairs
- Applied only to training data
- Enabled via `config['data']['augment']`

**Dual-Channel Mode:**
- Channel 1: Normalized flux values
- Channel 2: Extreme event indicator (binary: |flux| > threshold)
- Helps model focus on solar flares
- Enabled via `config['data']['dual_channel']`
