# V4 Ablation Matrix

11 arms. Each is a standalone YAML (no merge at runtime). All
share the production baseline except the listed delta. Each
writes to its own `outputs/ablations/<arm_id>/`.

Generated by `build_configs.py`.

| Arm | Δ from baseline | Tests |
|---|---|---|
| `A0_baseline` | production config (win128, zscore_per_cube, SA + tempattn + attngate, k5, [32,64,128]) | — |
| `A1_win64` | spatial scale: 64x64 windows (4x more samples, smaller receptive field) | smaller spatial scale beat baseline? |
| `A2_win192` | spatial scale: 192x192 windows (fewer samples, larger field, drops smaller cubes) | larger spatial scale needed? |
| `A3_signed_asinh` | norm: per-cube signed_asinh (heavy-tail compression vs linear zscore) | heavy-tail compression helps over linear zscore? |
| `A4_no_sa_convlstm` | ablate SA-ConvLSTM memory (use vanilla ConvLSTM) | is SA-ConvLSTM memory net positive at this scale? |
| `A5_no_temporal_attn` | ablate TemporalAttention over encoder hidden states | TemporalAttention worth its params? |
| `A6_no_attn_gate` | ablate AttentionGate on skip connection | AttentionGate worth its params? |
| `A7_channels_small` | smaller model: channels [16,32,64] (~4x fewer params) | does the small model underfit or close the gap? |
| `A8_kernel3` | smaller spatial receptive field per cell (kernel 3 vs 5) | is k=5 needed or does k=3 suffice? |
| `A9_tstride1` | denser temporal sampling: temporal stride 1 (4x more train samples) | more samples → better val? (overfit risk) |
| `A10_aug_aggressive` | all 6 D4 augmentations incl rotations (chirality-aware sign flips) | rotations + chirality flip improve generalisation? |
| `B0_convlstm_pure` | pure ConvLSTM: all 3 attention add-ons off (SA + tempattn + attngate), delta_scale + dropout kept | does pure ConvLSTM beat the full attention stack? (clean arch-only A0 vs B0; NOT the v2/v3 11-02 number — that compared different pipelines/epochs) |
| `S0_simple_convlstm` | minimal 2-layer SimpleConvLSTM, 1ch flux, hidden64 k3, L1, no AMP — canonical nowcasting baseline | can a minimal 2-layer ConvLSTM (canonical recipe) match the deep model? simplest viable baseline |
| `S1_simple_convlstm_noaug` | S0 minus augmentation, 4 epochs (~3h on CUDA) — isolates the value of D4 augmentation | does D4 augmentation help the simple model? S0 vs S1 (no-aug, 4ep, ~3h) |

## Run

```bash
python3 main.py --config configs/ablations/A0_baseline.yaml
# repeat per arm
```

## Compare runs

Each arm writes `outputs/ablations/<arm_id>/{best_model.pt,
training_history.json, test_results.json}`. Aggregate with
`generate_comparison.py` or a custom script that pulls val MAE,
CSI, HSS, SSIM per arm.

## Run order

1. **A0** first — establishes baseline.
2. **A4, A5, A6** in parallel — cheapest ablations (single feature off).
3. **A1, A2** — spatial-scale sweep (different sample counts).
4. **A3** — orthogonal normalisation choice.
5. **A7, A8** — architecture down-scaling (cheap).
6. **A9, A10** — sample-count + augmentation sweeps (longest).

If wall-clock is constrained, **A0 + A4 + A5 + A6** is the
minimum viable matrix for the v3.0→v4.0 ConvLSTM+attention story.
